# 2523/GHLP_BLE ラベルプリンター BLE プロトコル

出典: Android アプリ `com.feioou.deliprint.yxq` V3.9.1（versionCode 333）を jadx で逆コンパイルした結果
（`com.yxqapp.sdk.BluetoothPort` / `PrintL11` / `Printer_ESC`、`ContinuousPaperPrintActivity.P12CoPaPrint`）と、
2026-10-23〜24 に Mac から実機へ送って確かめた結果。アプリ内では「P12」系の派生機種（`GHLPByP12`）として扱われる。

実機: BLE 名 `2523/GHLP_BLE`、ファーム `V2.06`、シリアル `2523/GHLP78069`、15mm 幅の連続紙。

## 1. GATT

| UUID | 属性 | 用途 |
|---|---|---|
| service `0000ff00-0000-1000-8000-00805f9b34fb` | | 印刷用サービス |
| `ff02` | write / write-without-response | コマンドと印刷データを送る（TX） |
| `ff01` | notify | プリンターからの応答（RX） |
| `ff03` | notify | 流量制御（クレジット）と MTU 通知 |

ほかに `18f0`、`e7810a71-…`、`49535343-…`（Microchip の透過 UART）もあるが、このアプリは名前が `P80` で始まる機種だけ `49535343-…` を使う。

## 2. 接続手順と流量制御

1. 接続し、`ff03` と `ff01` の notify を有効にする。
2. `ff03` に `01 04` が届く（送信してよい回数＝クレジット 4）。続いて `02 64 00`（MTU 100）が届く。
3. `ff02` へ write-without-response で最大 **90 バイト**ずつ送る。1回送るごとにクレジットを1減らす。
4. プリンターは1パケット受け取るごとに `ff03` へ `01 01` を返す（クレジット +1）。クレジット 0 の間は待つ。純正アプリは 2 秒待っても来なければ 1 回だけ強制送信する。
5. 純正アプリはパケット間に 30ms 空ける（`getDataPacketDelay`）。定規の印刷では待たなくても欠けなかったが、同じ値にそろえている。

## 3. 照会コマンド（紙を使わない）

| コマンド | 意味 | 実機の応答（`ff01`） |
|---|---|---|
| `10 FF 40` | 状態 | `00`（正常） |
| `10 FF 50 F1` | 電池 | `1A 1F 21 00 59`（最後の1バイトが残量%、0x59=89%） |
| `10 FF 20 F1` | ファーム版 | `V2.06` |
| `10 FF 20 F0` | 機種名 | `2523/GHLP` |
| `10 FF 20 F2` | シリアル | `2523/GHLP78069` |
| `10 FF 30 11` | BT 名 | `2523/GHLP` |
| `10 FF 13` | 自動電源オフ時間 | `14`（20分） |

設定系（未検証）: 濃度 `10 FF 10 00 nn`、自動電源オフ `10 FF 12 hi lo`、ギャップ学習 `10 FF 03`、紙戻し `10 FF F2`。

## 4. 印刷ジョブ

純正アプリ（連続紙印刷）と同じ並び:

```
00 ×15                         起こす
10 FF F1 02                    印刷開始
1D 76 30 00 xL xH yL yH <data> GS v 0 ラスタ画像
1B 4A 64                       ESC J 100: 100 ドット（12.5mm）送る
10 FF F1 45                    ジョブ終了
```

- ラスタは 1 行 = `xL + xH*256` バイト、`yL + yH*256` 行。1 ビット 1 ドット、**1 = 黒**、各バイトの最上位ビットが左端。
- 印刷が終わると `ff01` に `AA` が届く（純正アプリも `AA` / `4F` / `4B` を成功扱い）。紙が出口の内側に残っていても `AA` は返るので、紙が出たことの証明にはならない。

### 画像の向きと大きさ（実機で測定）

- 1 行は紙の**幅方向**、行を重ねる方向が紙の**長さ方向**。文字を横書きで作り、時計回りに 90° 回してから送る（純正アプリと同じ）。
- 1 行のうち紙に出るのは**先頭 96 ドット（12 バイト＝12mm）だけ**。15mm 紙でも 120 ドットで作ると、後ろ 24 ドットが捨てられ、上下中央からずれる。8 ドット/mm（203dpi）。

### 注意: 先頭行が黒すぎると欠ける

画像の先頭に「96 ドット全部が黒い行」（枠の縦線など）があると、開始直後の約 30 行（約 4mm）が重なって消える。
95 ドットにしても少し欠け、先頭に白い行を 16 行（2mm）入れると欠けなくなった。印刷開始直後に紙送りが追いつかないためと推定している。
`labelprinter.protocol.print_job` は既定で先頭に白い行を 16 行入れる。
